# Schema DDL Implementation Plan

## Contract and Dependencies

Implement [schema/type/table/index/constraint administration](../../specs/ddl-schema.md) through the authenticated control path. Depend on [dictionary](../data-dictionary/README.md), [storage/index codecs](../storage-manager/README.md), [transactions](../concurrency-mvcc/README.md), [identity](../ddl-identity/README.md) and [permissions](../ddl-permissions/README.md). Query invocations reject DDL even for administrative principals.

## Decisions Before Implementation

Fix bounded DDL text/structured schemas, normalized identifier limits, scalar wire/storage ranges, exact decimal casts, UTC date/timestamp ranges and trusted default/CHECK IR. Preserve the declared initial scalar set, constraints and supported ALTER forms. Classify schema width, rewrite rows/bytes, and request sizes as configurable maintenance/schema workload budgets unless a catalog or ABI field is the actual constraint; the present 4096-column value is an implementation envelope, not a production target. Validate wide relations with the 80–250-column ERP/CRM sizing model, and plan a compatible catalog/metadata extension if the existing envelope is insufficient. Define deterministic fence acquisition, affected-table schema/write epochs and private-build publication/cleanup without custom physical trees.

| DS-8 | An authenticated administrator can express basic schema and table creation/lifecycle in SQL without sending DDL to query execution | Parse bounded schema/table create, rename, RESTRICT drop, and key-constraint ALTER statements in the client; expose through authenticated `admin-sql`; translate to existing typed operations and retain server-side authorization/catalog validation |

| DS-SQL-50 | A named CHECK in CREATE TABLE is published atomically with its name and expression | Parse column- and table-level `CONSTRAINT name CHECK` forms, bind names to expressions in a versioned `tables.create` request, persist names in catalog objects in the same table-creation commit, and reject duplicate names within one statement |
| DS-SQL-51 | Named PRIMARY KEY, UNIQUE, and FOREIGN KEY definitions are discoverable and droppable by name | Extend CREATE TABLE naming across all constraint kinds, carry aligned names in `tables.create` v4, persist names in the atomic catalog commit, reject statement-wide collisions, expose names through constraint metadata, and resolve SQL DROP CONSTRAINT by name |

| DS-SQL-53 | Administrators can express common finite-set checks in SQL | Add typed-literal column `IN` and `NOT IN` predicates to CREATE TABLE and ALTER CHECK parsing, cap lists at 64 values within the EIR1 evaluation budget, bind literals to the column type, and preserve SQL UNKNOWN semantics through the existing Boolean evaluator |
| DS-SQL-54 | Administrators can declare inclusive scalar ranges in SQL constraints | Add column `BETWEEN` and `NOT BETWEEN` over typed literals to CREATE TABLE and ALTER CHECK parsing, lower to inclusive comparisons using existing EIR1 nodes, and preserve NULL/UNKNOWN behavior |
| DS-SQL-55 | Administrators can express null-safe equality checks | Add `IS [NOT] DISTINCT FROM` against one typed literal in CREATE TABLE and ALTER CHECK parsing; lower to bounded EIR1 null checks/comparisons without changing protocol encoding |
| DS-SQL-56 | Administrators can test Boolean values including SQL UNKNOWN in CHECK and policy SQL | Accept `IS [NOT] TRUE`, `FALSE`, and `UNKNOWN` only on BOOLEAN columns; lower the two-valued tests to existing EIR1 null, equality, AND, and NOT nodes |
| DS-SQL-57 | Boolean truth tests accept grouped predicates and policy expressions | Bind any Boolean-valued operand, including parenthesized comparisons/conjunctions and policy-context functions where allowed, while keeping EIR node and statement-size bounds |
| DS-SQL-58 | Null tests accept supported scalar expressions | Bind `IS [NOT] NULL` against any supported scalar expression in CREATE TABLE CHECK and ALTER CHECK SQL, preserving EIR1 null semantics and column dependency binding |
| DS-SQL-59 | Null-safe distinctness tests accept supported left expressions | Bind `IS [NOT] DISTINCT FROM` with any supported scalar expression on the left and one typed literal on the right, preserving two-valued NULL semantics through existing EIR1 nodes |
| DS-SQL-60 | Finite-set and range predicates accept supported expressions | Bind `IN`/`NOT IN` and `BETWEEN`/`NOT BETWEEN` against supported scalar expressions, contextually type literals, and reject expanded EIR1 trees that exceed the canonical node/depth/byte bounds |
| DS-SQL-61 | Null-safe distinctness accepts expressions on both sides | Bind both operands of `IS [NOT] DISTINCT FROM` as supported typed scalar expressions and lower the four NULL/value combinations to a two-valued EIR1 predicate within canonical bounds |
| DS-SQL-62 | Finite-set and range values accept scalar expressions | Allow supported scalar expressions inside `IN` lists and as `BETWEEN` bounds, contextually bind them to the tested operand type, preserve SQL UNKNOWN semantics, and enforce final EIR1 bounds |
| DS-SQL-63 | Comparisons accept grouped expressions on both sides | Extend comparison parsing to accept a parenthesized supported scalar expression as the right operand, then use existing contextual binding and type checks without changing EIR1 |
| DS-SQL-64 | CHECK constraints can enforce bounded integer arithmetic rules | Add typed SMALLINT/INTEGER/BIGINT `+`, `-`, and `*` scalar expressions with SQL NULL propagation and checked overflow; encode arithmetic as bounded EIR1 nodes and keep DECIMAL arithmetic/division out of scope |
| DS-SQL-65 | CHECK constraints can test integer remainders | Add typed SMALLINT/INTEGER/BIGINT `%` expressions at multiplicative precedence, preserve SQL NULL propagation, fail closed for zero divisors and signed overflow, and extend EIR compatibility without changing catalog metadata |

## Acceptance and Handoff

Use actual administrative prepare/start/status operations and real redb data. Cover default changes versus backfill, duplicate/existence checks after authority, graph races, hidden constraint diagnostics, old readers after rename/drop and crash/reopen during publication. Initial scope is incomplete without unique/FK constraints and the supported DDL forms. First behavior: one authorized schema/table creation and a denied control request, once minimal identity/catalog plumbing exists.
| DS-SQL-66 | CHECK constraints can express bounded integer quotients | Add same-type SMALLINT/INTEGER/BIGINT `/` expressions at multiplicative precedence, truncate toward zero, propagate NULL, fail closed on zero divisors and signed overflow, and extend EIR compatibility while keeping DECIMAL arithmetic out of scope |
| DS-SQL-67 | CHECK constraints can negate integer expressions | Add unary `-` for SMALLINT/INTEGER/BIGINT scalar expressions, propagate NULL, fail closed when negating the signed minimum, and version the EIR opcode while preserving prior decoders |
