# Executor Progress

## EX-1 dependency: freeze the initial C entry-point ABI

- Behavior: Linux x86_64 query libraries use a sized/versioned descriptor, `prdb_query_main_v1`, a sized host record, and a sized invocation record containing immutable borrowed parameters. `BorrowedInvocationV1` ties the raw pointer to the parameter slice, uses NULL only for zero length, and enforces the 1 MiB cap. The initial host record exposes no callbacks; storage, planning, result, and cancellation services remain future ABI work.
- Contract and code: [query worker ABI](../../specs/query-worker.md), [client SDK entry point](../../specs/client-sdk.md), [public v1 header](../../engine/include/prdb_query_abi_v1.h), and [Rust ABI definitions](../../engine/src/query_abi.rs).
- Regression: Rust tests assert x86_64 C size/alignment/offsets, reject descriptor ABI, size, host-table, and invocation-record mismatches, and verify parameter pointer lifetime construction, empty NULL representation, and size bounds. A TinyCC `_Static_assert` fixture independently compiles the public header layout without loading a library.
- TDD evidence: the focused Rust ABI test first failed to compile because the `query_abi` module did not exist; it passes against the implemented records and validator.
- Verification: focused Rust tests passed (3/3). TinyCC 0.9.27-unstable-2025-01-06 compiled `query_abi_v1_layout.c` to an ELF object. The object was not linked into or loaded by a process. Full workspace formatting, build, warning-denied Clippy, all tests, TinyCC header compilation, and `git diff --check` passed after the bounded marshalling addition.
- Remaining: implement the clean executor host and confined load/descriptor/entry validation, define storage/result callbacks, and exercise compatible/mismatch artifacts only through the full sandbox harness.

## EX-1 dependency: clean post-exec worker host and launch orchestration — implemented, service wiring pending

- Behavior: `prdb-executor --library ABSOLUTE_PATH --parameters-fd FD` verifies PID 1, `no_new_privs`, and empty effective/permitted/inheritable/bounding capability sets; then it installs seccomp, opens the library, validates the v1 descriptor, resolves `prdb_query_main_v1`, reads parameters with a 1 MiB cap, and calls the entry point. It retains the mapping and exits the process without unloading arbitrary code. `--self-check` exercises startup and seccomp without loading a library.
- Changed code: [executor host binary](../../engine/src/bin/prdb-executor.rs), [ABI contract](../../engine/src/query_abi.rs), and [Linux hook configuration](../../engine/src/linux_sandbox.rs).
- Regression: [executor host tests](../../engine/tests/linux_sandbox.rs) launch `--self-check` through namespaces, Landlock, clean descriptors/environment, and a test cgroup hook; direct unconfined invocation is rejected before loading.
- Observed limit: these tests do not load a query library and do not use a real delegated cgroup. This host's cgroup parent is read-only; the artifact loader's real dynamic-loader, constructor, descriptor mismatch, and entry-point path remain unverified until the complete profile is available.
- Verification: the focused executor tests passed (2/2); full workspace formatting, build, warning-denied Clippy, and tests passed. The artifact-loading path was not invoked.
- Launch orchestration: [executor launcher](../../engine/src/executor_launcher.rs) materializes the sealed artifact in a private read/execute-only directory, passes parameters through a sealed memfd, applies Landlock and the established pre-exec chain, admits storage only after launch preparation, spawns the executor, and ties process exit/cgroup cleanup to `SupervisorInvocation`. Tests cover artifact permissions and removal, parameter sealing, and unsupported-profile rejection before admission.
- Observed limit: the new process launch path has not been spawned on this host because its cgroup parent is read only. No query artifact was loaded. Runtime library paths must be supplied by a pinned deployment profile.
- Gateway integration: the Linux x86_64 gateway service listener now routes network START through the token-revalidating executor orchestration and returns the running worker with its storage invocation to the trusted callback. The regression verifies the listener remains available and authenticated START rejects an unsupported cgroup host before storage admission, leaving no snapshot/outcome.
- Channel integration: the launcher creates separate planner/executor Unix socket pairs, passes the worker ends through the clean descriptor setup, and `RunningExecutor::observe_exit` serves both trusted endpoints concurrently before exit/cgroup observation. The executor host retains the descriptors, but v1 exposes no callbacks for them.
- ABI v2 contract: added a separate C header and Rust layouts for a sized host table with executor/planner request callbacks and provisional result output. Bounds are 1 MiB per IPC request/response, 16 KiB per output call, and 64 MiB cumulative output; v1 remains unchanged. Rust tests check x86_64 C layout and reject descriptor version/size mismatches.
- Result transport: the launcher provisions a third Unix stream for result bytes and passes only the worker endpoint through the clean descriptor setup.
- Runtime v2 callbacks: the confined host prefers a validated v2 descriptor, binds synchronous request callbacks to role-allowlisted framed planner/executor streams, and exposes bounded result writes. `RunningExecutor::observe_exit_with_results` drains output concurrently with storage channel service, invokes a trusted per-chunk relay callback, and kills/reaps on channel or relay errors. A gateway helper emits correlated `0x1410` data events but leaves terminal decisions to the storage owner. Callback tests cover framed request/response, cross-role denial, output framing, cumulative quota rejection, and gateway event encoding.
- Remaining: connect the observer callback to gateway `0x1410` events and storage-confirmed `0x1411` terminal events, establish a writable delegated cgroup parent, and test compatible/mismatch C libraries only through the complete sandbox harness. Add cancellation and statement-level transaction callbacks in the ABI integration.
