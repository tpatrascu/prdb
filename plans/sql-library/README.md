# SQL Library Implementation Plan

## Contract and Dependencies

Implement the C [SQL frontend/interpreter](../../specs/sql-library.md) in the prebuilt TinyCC SDK archive. Depend on [SDK/ABI](../client-sdk/README.md), [optimizer](../planner-compiler/README.md), [authorized storage](../authorization/README.md), [transactions](../concurrency-mvcc/README.md) and [schema types](../ddl-schema/README.md). No SQL/native query code runs inside trusted storage.

## Decisions Before Implementation

Specify grammar/parameter syntax, AST and physical-plan formats, SQL API and result encoding. Fix typed coercions, overflow/decimal/date semantics, Boolean/null logic, evaluation/error order and redaction behavior before rewrites/operators rely on them. Initial syntax is single-table SELECT/WHERE/LIMIT and INSERT/UPDATE/DELETE; reject DDL, explicit transaction control, unsupported syntax and reentrant/concurrent statements.

SQL-7's HAVING type coverage proceeds through separately versioned SDK increments. V21 adds exact signed integer, fractional, and exponent literals for compound grouped HAVING, with decimal scale coercion checked before scans; earlier parser and binding ABIs remain frozen. V23 adds selected-aggregate and hidden COUNT(*) `IS [NOT] NULL` leaves to compound HAVING while preserving earlier parser/binder behavior. V24 extends the same HAVING behavior to a single grouping key and adds COUNT(column) as aggregate tag 6. The existing aggregate optimizer request and plan forms carry its argument column; the SDK matches the plan and executes the bounded v24 runner. The typed grouped and filtered JOIN runners bind PSP1 operand types and Decimal scales before scanning, including typed NULL and LIMIT 0. Acceptance evidence belongs in [`PROGRESS.md`](PROGRESS.md), and broader analytical type/workload coverage remains open. SQL-9 adds spill as a separate implementation increment; it does not weaken or replace current bounded in-memory execution. Administrative SQL DDL is owned by the schema DDL plan and uses the separate authenticated control client; it is not added to the query-invocation SQL dispatcher.

### SQL-9 secure spill decisions and acceptance

The normative spill contract is in [SQL library](../../specs/sql-library.md), [workload profile](../../specs/workload-profile.md), [Linux sandbox](../../specs/linux-sandbox.md), and [supervisor](../../specs/supervisor.md). `PSPL` v1 framing, operation codes, and the sized Host API v6 callback are recorded in [`PROGRESS.md`](PROGRESS.md). The maintained SDK exposes opaque stream operations and a stable external merge-sort primitive. ABI v6 row SELECT dispatch sends ordered queries through that sorter; each encoded row record is fixed at 1024 bytes and a larger individual row fails the statement before sorted output starts. The alias-aware composite/filtered v20 JOIN path streams authorized scan rows into eight hash partitions and evaluates bounded 128 by 128 blocks, including skewed partitions; fixed records are capped at 4096 bytes. Its SQL dispatch uses the opaque broker and applies SQL equality, filters, LIMIT, result encoding, and statement-failure handling. V25 adds one qualified projected ORDER BY column to this JOIN shape. ABI v6 spools fixed 1024-byte joined projection records, sorts them with the stable external sorter, and applies LIMIT after sorting; a larger record aborts before SQLR output. The temporary spool overlaps the 16 JOIN partition streams, so configure at least 17 simultaneous streams per invocation for combined JOIN ORDER BY. Single-key v8 JOIN statements are normalized to an equivalent duplicate-key v20 predicate and use the same spill runner. ABI v6 also spills unordered `COUNT(*) GROUP BY` queries without `WHERE` or `HAVING`: it sorts fixed 1024-byte encoded key tuples, folds equal keys in a streaming pass, and applies LIMIT to the sorted groups. Other grouped query shapes remain on the bounded v24 path. The broker rejects tmpfs and ramfs, requires `fstatvfs` headroom, and probes one filesystem allocation unit with `posix_fallocate` at startup; the supported production filesystem matrix still needs deployment validation. All seven configuration flags are required together and absent configuration disables spill. The sorter uses 64 KiB run-building and merge-output buffers, fixed records up to 1024 bytes, a maximum eight-run merge fan-in, and 64-bit stable input ordinals. Row ORDER BY and spilled grouping each hold one source stream in addition to the sorter's eight input runs and merge output, so configure at least ten simultaneous streams per invocation. The hash join opens 16 partition streams; configure at least 16 when this operator is enabled, plus any streams used concurrently by downstream operators. A deterministic broker test confirms a blocked append in one package does not prevent another package from creating a stream, and the confined pressure mode overlaps broker-backed sort with operational reads and commits. Sustained fairness measurements under service-wide disk saturation remain open. Do not add encryption; temporary spill data is plaintext and host-level disk confidentiality remains within the host trust boundary.

Acceptance must prove that the executor receives neither scratch paths nor file descriptors; the broker rejects cross-invocation, cross-package, stale, malformed, oversized, cancelled, and over-quota operations; actual allocated blocks remain within the configured caps; and all files are reclaimed after success, error, cancellation, timeout, worker crash, and broker restart. Confined ABI v6 GROUP BY COUNT(*) acceptance runs against the real broker, checks exact SQLR rows including duplicate NULL keys, verifies spill-disabled fallback, checks post-group LIMIT, and confirms a one-byte allocation quota aborts durably with no result rows. Confined ORDER BY checks NULL placement, Decimal ordering, and exact SQLR results; a restrictive cell policy confirms that sorting a REDACTED Decimal key aborts before SQLR output. Composite JOIN checks its SQLR multiplicities and confirms NULL keys do not match. A separate confined worker-crash mode writes to a spill stream, emits provisional output, faults the process, and checks durable abort plus package cleanup. SDK fixtures independently cover stable external sort ordering and skewed join partitions; broader confined result comparison remains open. A deterministic broker test pauses one package in append allocation and confirms another package can create a stream, while confined spill pressure overlaps operational reads and commits. Sustained service-wide disk saturation with concurrent cancellation/commit-control checks remains open. Supported filesystem deployment validation remains open. Physical ENOSPC during SQL spill must abort the invocation without partial durable writes. Unsupported scratch filesystems are rejected during supervisor startup before a SQL invocation can be admitted, so that failure is verified at the process startup boundary rather than through SQL. All query code and spill integration fixtures run only through the confined executor.

## Acceptance and Handoff

Physical filesystem exhaustion is also exercised by the confined SQL-9 disk-full acceptance: it fills a separate ext4 filesystem after broker startup and verifies that a spill ORDER BY allocation failure emits no SQLR rows and resolves as durable ABORTED. The reproducible setup and environment variables are in [`SANDBOX_TEST.md`](SANDBOX_TEST.md).

The opt-in `PRDB_TEST_SPILL_FILESYSTEM_ROOT` broker probe also passed on this host's NFSv4.2 workspace mount. It opened the broker, reserved spill allocation, round-tripped an 8 KiB stream, and reclaimed the package files. This single development-host smoke test does not establish NFS deployment support or replace the target-filesystem allocation, exhaustion, locking, and recovery matrix.

The `PRDB_TEST_SPILL_PRESSURE_CANCEL_ONLY` acceptance runs concurrent broker appends/seals while four operational workers perform 64 point reads and 64 durable commits, then requests owner cancellation during spill activity. It verifies that cancellation is accepted and the operational work finishes while the spill invocation durably aborts. Longer service-wide saturation and target-filesystem validation remain deployment work.

Maintain a feature/type/operator matrix against specs and compare interpreter results/errors with small independent authorized-view fixtures. Fuzz the C parser separately from Rust query/plan decoders. C unit executables are maintained SDK tests; query artifacts run only through the sandbox harness. Initial SQL completion does not complete analytical support. First behavior: one supported SELECT parse fixture and one unsupported-statement error, once grammar and bounds are specified.
