# Statistics Service Implementation Plan

## Contract and Dependencies

Implement [statistics](../../specs/statistics-service.md) as a trusted module within [storage](../storage-manager/README.md). Depend on [authorization](../authorization/README.md), [snapshots/overlays](../concurrency-mvcc/README.md), [dictionary validity](../data-dictionary/README.md) and planner-role [IPC](../ipc-protocol/README.md). A separate collector process and global statistics are not initial prerequisites.

## Initial Implemented Slice

The internal `InvocationTransaction::estimate_authorized_scan` API returns exact visible-row and requested-column VALUE/NULL/REDACTED counts from the pinned snapshot plus private overlay, or `Unknown` without partial counts. It scans at most 16,384 candidates per estimate and the planner metadata connection admits at most 16 estimates over its lifetime; exhaustion returns `Unknown` while leaving the invocation active. It returns exact results only for policy shapes with row inclusion independent of row values: literal policies can prove a full population or an empty population without scanning rows. Value-dependent policies and invalid contexts return `Unknown` before scanning. Ordinary unordered single-table SELECT can opt into a population probe capped at four rows, reading at most five row keys. Join planning can request up to 128 rows per relation, reading at most 129 row keys. Both probes avoid decoding row values and share the planner's estimate allowance. For joins, exact empty inputs, two known populations of at most four, and two known populations above four select hash join. Exactly one known 1–4-row side can be selected as outer when the opposite side has an eligible index; the measured medium-population fallback reflects the local 64×64 benchmark. Other unknown estimates preserve the documented fallback. This is only an orientation heuristic; join result cardinality, probe fanout, predicate selectivity, and general cost comparison remain unimplemented. An exact empty SELECT population can produce the validated no-scan hint; exact populations 1–4 can select a sequential scan over an indexed path using the measured local cutoff. `planner_ipc` dispatches relation descriptions and estimates through connection-scoped kind-9 handles. The trusted transaction layer additionally supports exact predicate-match counts for authorized populations up to 16,384 rows when all referenced cells are readable; redacted or unsupported predicates return `Unknown`. The planner-only EstimateScan operation accepts bounded bound-predicate requests by qualified relation name and returns exact visible/matching counts or `Unknown`. Exact predicate results may be reused within their planner session when relation/schema, predicate, bound, snapshot, and private-write generation still match. For filtered ordinary unordered single-table SELECT, the optimizer uses exact zero matches for the no-scan hint. For nonzero results, it uses `visible_rows` to choose a sequential scan when the full authorized population is 1–4, and uses exact `matching_rows` to choose a sequential scan over a range path when at least half the authorized rows match. Unique point probes remain unchanged; `Unknown` preserves the ordinary plan. The SDK re-resolves the relation and checks cancellation before skipping an empty scan. The IPC role matrix denies estimate operations to executors and executor scan operations to planners. `SupervisorInvocation::serve_worker_channels` provisions the planner and executor storage streams concurrently and drains both before worker-exit observation. Estimate requests execute synchronously on their provisioned planner stream; there are no detached planner tasks. A separate bounded trusted collector writes a sequence-tagged global table population to the protected rebuildable stats table; the gateway maintenance loop schedules one catalog-cursor table refresh per configured interval, defaulting to 15 minutes in the supervisor. No collection operation is exposed to planner or executor IPC. Planner use of collected global counts, broader cost choices, additional statistics fields, and asynchronous estimate scheduling remain unimplemented.

## Decisions Before Further Implementation

The bounded trusted predicate contract reaches planner IPC and supports SELECT empty-result/access hints for exact authorized populations up to the 16,384-row estimate candidate budget. Join planning uses authorized population estimates capped at 128 rows per input. Exactly one known 1–4-row side may use an eligible opposite-side index; exact-empty inputs, two small inputs, and two known populations above four retain hash join. This remains a bounded measured heuristic: cost-based algorithm selection, join populations above 128, join fanout, and estimate-informed candidate comparison remain deferred. Exact predicate, population, and column-summary reuse is scoped to one planner session and invalidated by every private write; additional estimate forms may be cached only with complete principal/grant/policy/data/schema validity and without crossing principals. Fix which logical access-path information is public; never release physical counts, global epochs/costs or raw samples indirectly.

## Increments

| ID | Observable test first | Minimum implementation and evidence |
| --- | --- | --- |
| ST-1 | Executor calling estimate/refresh and planner requesting unrestricted data are denied | Implemented at provisioned planner/executor streams: planner-only relation handles and estimate operations are dispatched under the planner role; executor streams reject `EstimateScan`, planner streams reject `OpenScan`, both emit no response and durably abort on cross-role requests. The fixed operation matrix is also tested independently |
| ST-2 | Scoped visible/readable/null/redacted populations match a reference authorized scan | The full summary, statically empty population, bounded exact population probe, and bounded trusted predicate-match estimator for 0–16,384 rows are implemented; optimizer uses estimates for SELECT access choices and join orientation, while general cost-based selectivity and broader policy-filtered estimates remain |
| ST-3 | Changing hidden values or adding invisible rows leaves normalized released estimates unchanged | Paired authorized-view comparisons verify unchanged visible rows and `Unknown` estimates across differing hidden candidate counts; real-redb regressions confirm changing only a redacted cell leaves exact predicate counts and sanitized populations unchanged, while adding invisible candidates under a value-dependent row policy continues to return `Unknown`. Timing/resource noninterference and broader estimate fields remain |
| ST-4 | Estimate-specific exhaustion returns unknown, but context cancellation/deadline drains and terminates | Verified for the synchronous estimate path: budget exhaustion returns `Unknown` without partial counts; cancellation/deadline terminate the estimate stream and worker without fallback, and supervisor finalization waits for provisioned channels to drain. No detached planner task queue is used |
| ST-5 | A private write or changed authorization context prevents stale summary reuse and cross-invocation leakage | Exact predicate results, bounded population probes, and exact column summaries are cached only within one planner session. Keys include relation/schema identity and their complete request shape: predicate bytes plus bound, population row bound, or ordered requested column IDs. The session pins authorization and snapshot context, and every private overlay mutation invalidates all caches by generation. Cache hits still consume the shared estimate allowance. Unknown and cross-session results are not cached |
| ST-6 | Later private collection is bounded, undisclosed and cannot starve commits | Implemented slice: one committed-snapshot row-population pass, capped at 16,384 rows with no partial result, one shared maintenance admission slot, `CPR1` source-sequence tagging in the protected `stats_v1` table, and no count in the public maintenance outcome. The gateway schedules one table per configured interval using a wrapping catalog cursor. Tests verify stale-sequence tagging, `Unknown` on overflow, clone-shared single admission, operational commit during collection, and cursor wrap. Richer statistics and trusted planner consumption remain |

## Acceptance and Handoff

Use authorized-view reference fixtures with nulls/redactions and repeated chosen-predicate probes. A sample lacking redactions is not permission to execute an aggregate, and readable-only summaries never redefine SQL semantics. Record planning overhead/quality on selective policies and mixed workloads before richer sampling. Timing/cache noninterference is not established by normalized-content tests; estimate caches remain invocation- and planner-session-scoped.
