# On-Disk Storage Format v1

## Scope and Conventions

This is the initial proposed format for the operational row store. Format version is `1`; there are no existing databases to migrate. Use explicit little-endian integers, checked offsets, zeroed reserved bytes, and CRC32C checksums. UUID/object IDs are opaque 16-byte strings with canonical byte order. Never serialize Rust/C struct memory. Unknown required flags, nonzero reserved fields, invalid lengths, or unsupported versions fail validation.

Data pages are 16,384 bytes, aligned to their file offsets. Pages are grouped into 64-page, 1 MiB allocation extents. These are logical sizes, not assumptions about atomic device writes or direct-I/O alignment. See [WAL](wal-recovery.md) for torn-write recovery and [I/O](disk-io.md) for durability operations.

## Directory and Root Files

Within an exclusively owned database directory, use internal files `root.0`, `root.1`, `data/<file-id>-<generation>.dat`, `wal/<segment-number>.wal`, and `checkpoint/<generation>.manifest`. Names are generated by storage, never supplied as query paths. No executor may open these files. Temporary build files have separate unpublished identities.

Each root file is a 4,096-byte record: magic `PRDBROOT` (8), format u16, header length u16=128, CRC32C u32, database UUID (16), root generation u64, checkpoint generation u64, checkpoint replay-start LSN u64, committed frontier u64, storage/catalog/WAL versions (three u32), reserved u32, checkpoint SHA-256 (32), required features u64, lifecycle state u32, reserved u32; remainder zero. Checksum covers all bytes with the checksum field zero. Hash/checksum detect corruption, not malicious modification.

[Checkpoint format v1](checkpoint-format.md) defines the manifest, lifecycle/feature codes, writer-build identity location, and exact binding to these root fields.

Alternate root slots: write and sync the inactive slot only after its checkpoint manifest and required files are durable. Startup selects the highest generation whose entire referenced checkpoint chain validates. If the newest root is torn, recover from the older valid checkpoint plus retained WAL. A valid newest root referencing corrupt required data is not permission to silently lose acknowledged commits by falling back. Unsupported required formats fail closed.

## Common Page Header

Every data page has this exact 128-byte header:

| Offset | Bytes | Field |
| --- | --- | --- |
| 0 | 8 | `PRDBPAGE` magic |
| 8 | 2 | Format version |
| 10 | 2 | Kind: heap=1, B-tree=2, overflow=3, allocation=4 |
| 12 | 2 | Header bytes=128 |
| 14 | 2 | Flags |
| 16 | 16 | Database UUID |
| 32 | 16 | Logical storage object ID |
| 48 | 8 | File ID |
| 56 | 8 | File generation |
| 64 | 8 | Page number within file |
| 72 | 8 | Page allocation generation |
| 80 | 8 | Page LSN of its latest full-page WAL image |
| 88 | 4 | CRC32C of the full page, with this field zero |
| 92 | 2 | Slot count |
| 94 | 2 | Lower used boundary |
| 96 | 2 | Upper free boundary |
| 98 | 2 | Reserved |
| 100 | 8 | Structural revision |
| 108 | 20 | Reserved |

Check identity, ownership, generation, boundaries, slot overlap, checksum, and supported kind before interpretation. Page numbers are physical locators, not logical object IDs. A physical record reference is 40 bytes: file ID u64, file generation u64, page number u64, page generation u64, slot u32, slot generation u32. All-zero is a null reference.

## Heap Pages and Version Records

Heap pages use 16-byte slots growing upward from offset 128: payload offset u16, payload length u16, flags u32, slot generation u32, reserved u32. Payloads grow downward, aligned to 8 bytes. Compaction moves payload bytes but preserves slot identity. Reusing a slot increments its generation after all old references are reclaimable. Zero free/padding bytes when generating a persisted page image.

A row version starts with a 112-byte header: magic `ROW1` (4), format u16, flags u16, record bytes u32, header bytes u32=112, row UUID (16), begin commit u64, end commit u64, previous-version reference (40), table schema version u64, column count u32, reserved (12). End=`UINT64_MAX` means not yet superseded. Tombstones have a flag and no fields. Committed versions are visible for `begin <= snapshot < end`; private versions live only in the transaction arena until commit.

The header is followed by one 16-byte field descriptor per column: state u8 (value=0/null=1), storage u8 (inline=0/overflow=1), reserved u16, row-relative offset u32, logical byte length u32, auxiliary u32=0. Null descriptors have zero offset/length/storage. Persist no REDACTED state: redaction is a permission-filtered output representation, not stored user data.

Column ordinal/type resolution uses the row's schema version and stable catalog column IDs. Retain required old schema definitions as long as stored versions need decoding, even if no current reader pins them. An added column absent from an old record resolves through the versioned add-column literal default or null, never the latest default. Dropped fields remain physical until safe rewrite/reclamation.

## Scalar and Overflow Values

Boolean: one byte 0/1. Integers: signed 16/32/64-bit two's-complement little-endian. Decimal: signed i128 unscaled coefficient with scale/precision from schema; reject overflow. UUID: 16 bytes. DATE: signed i32 days since 1970-01-01, with SQL-valid range validation. TIMESTAMPTZ: signed i64 UTC microseconds since that epoch; no infinite/NaN special values initially. TEXT/VARCHAR: validated UTF-8 bytes without a terminator. BYTEA: uninterpreted bytes.

Initial limits are 256 columns, 8 KiB inline row record, and 16 MiB per scalar value. Variable values over 4 KiB use overflow; move additional largest variable fields out-of-line as needed to meet the row limit. Fixed-width oversized rows fail rather than silently changing layout. Overflow descriptors point at a 40-byte reference; the descriptor length is the full logical value length.

Overflow pages use the common header, then next-page reference (40), chunk length u32, reserved u32, and payload from offset 176. No slots; referenced slot/generation are zero. Validate total length, ownership, chain termination, and cycles before materializing a value. Pin each traversed page. No deduplication of secret values across principals; unchanged overflow chains may be shared internally between versions of the same row with explicit reachability retention.

## B-tree and Row Directory

Maintain a primary internal row-directory B-tree mapping stable row UUID to the latest committed version reference. Old snapshots traverse version chains; readers never receive a physical pointer. Secondary indexes retain entries for old versions until the same reclamation horizon permits removal. Index lookup still validates row visibility and permissions, including when a key matches.

B-tree pages reserve bytes 128–223 for level u16, flags u16, entry count u32, right sibling reference (40), leftmost child reference (40), reserved (8). Slots start at 224 and use heap slot format. Leaf level is zero. Each entry has prefix `key_bytes u32, value_bytes u32, flags u32, reserved u32`, then key and value. No prefix compression initially. Internal entries map separator keys to right-child page references; child references have zero slot fields. Siblings/separators update atomically through one commit's logged page images.

[Index-key encoding v1](index-key-encoding.md) fixes component markers, numeric transforms, variable-value escaping, suffixes, separators, and range bounds. Secondary ties append raw row UUID and big-endian begin commit; values reference row versions. Unique enforcement compares only the user-key prefix against relevant live committed/private rows, with SQL null rules. The 2,048-byte complete-key limit includes the 24-byte secondary suffix, leaving 2,024 bytes for SQL tuple components. Oversize indexed values fail explicitly.

Row-directory keys are row UUID bytes. Catalog records use typed, versioned field-tag payloads on the same page infrastructure with built-in definitions; they are not SDK-accessible heaps. [Catalog payload v1](catalog-payloads.md) fixes the logical family envelopes/TLV fields and their ROW1 container. Allocation records track each extent's page ownership/generation/state and retire horizon; their separate payload schema still needs specification before format v1 implementation is declared complete.

## Publication, Reuse, and Tests

Construct one private page image per changed page during final commit preparation. Log complete after-images before publication; no uncommitted page is flushed to a database file. Publish images, roots, and MVCC changes under the commit gate. This deliberately trades page-copy/WAL volume for simpler initial recovery; [memory storage](memory-storage.md) bounds and accounts for it.

Test all header offsets, endian/scalar round trips, malformed descriptors, overflow cycles, schema evolution, page/slot reuse, duplicate index keys, old-snapshot index reads, and torn pages. The constants above are design choices, not performance findings; changes require an explicit format-version review.
